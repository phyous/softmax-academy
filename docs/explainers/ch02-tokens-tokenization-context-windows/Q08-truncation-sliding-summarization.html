Truncation vs Sliding Windows vs Summarization

Chapter 2 / Q08 — Three Strategies for Context Overflow

Quick Take

Three ways to handle too-long input. Truncation is a guillotine -- fast but ruthless. Sliding windows are a spotlight scanning a dark room. Summarization is a note-taker who captures the gist but loses the quotes. Each trades off speed, fidelity, and coverage differently.

Deep Dive

Truncation drops tokens from the start or end -- O(1) complexity, zero compute overhead, but potentially catastrophic if it cuts instructions or key evidence. A prompt that says "summarize the document above and answer the question below" loses all meaning if the question at the bottom gets truncated. In practice, most frameworks default to truncating from the start (keeping the most recent tokens), which works for chat but fails for document analysis.

Sliding windows process the document in overlapping segments, each fitting within the context limit. This preserves local detail and handles arbitrarily long documents, but the model never sees the full picture at once -- cross-document reasoning suffers. You need a merge step to combine window outputs, and that merge step introduces its own failure modes. The overlap between windows is critical: too little and you miss information at window boundaries, too much and you waste tokens on redundancy.

Summarization uses a model (or heuristic) to compress earlier content into fewer tokens. It preserves intent and gist better than truncation, but introduces abstraction loss: exact numbers, quotes, and edge cases may vanish. In production, teams often combine strategies: summarize old conversation history, retrieve the most relevant chunks via embedding search (not all chunks), and reserve a strict token budget for the model's output. The best strategy depends on your data -- structured data tolerates truncation better; narrative text benefits from summarization.

Code

def truncate(tokens, max_len, side="end"):
    """Drop tokens from start or end."""
    if side == "end":
        return tokens[:max_len]
    return tokens[-max_len:]

def sliding_window(tokens, window_size, stride):
    """Yield overlapping windows."""
    for i in range(0, len(tokens), stride):
        yield tokens[i:i + window_size]

def summarize_and_append(old_context, new_context, budget):
    """Compress old context, keep new context full."""
    # In practice: call LLM to summarize old_context
    summary = old_context[:budget // 4]  # placeholder compression
    return summary + new_context[:budget - len(summary)]

# Demo
doc = list(range(100))  # 100 "tokens"
print("Truncate (keep 30):", truncate(doc, 30))
print("Windows (size=20, stride=15):",
      [list(w) for w in sliding_window(doc, 20, 15)])
print("Summarize+Append:",
      summarize_and_append(doc[:60], doc[60:], budget=50))
