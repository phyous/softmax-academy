What is a Context Window?

Quick Take

The context window is the model's working desk — everything it can see at once. System prompt, user input, retrieved docs, conversation history, and the answer it's generating all compete for the same fixed space.

Interactive Visual

Overflow! Your allocations exceed the context window. The model will truncate conversation history and retrieved context first.

Deep Dive

A context window isn't memory — it's more like RAM. The model can only attend to what's inside it during a single forward pass. A "128k context" model accepts 128,000 tokens total, not 128,000 words (which would be roughly 170,000 tokens). Everything competes: system instructions eat tokens, retrieved passages eat tokens, and critically, the model's own output eats tokens from the same budget.

This is why context management — deciding what goes in, what gets summarized, and what gets dropped — is a core engineering skill, not an afterthought.

Code

def budget_context(total_window: int, system: int, history: int,
                   retrieval: int, query: int, output_reserve: int) -> dict:
    """Plan a token budget and check for overflow."""
    used = system + history + retrieval + query + output_reserve
    remaining = total_window - used
    budget = {
        "total_window": total_window,
        "system_prompt": system,
        "history": history,
        "retrieval": retrieval,
        "query": query,
        "output_reserve": output_reserve,
        "used": used,
        "remaining": remaining,
        "overflow": remaining < 0
    }
    return budget

plan = budget_context(
    total_window=128000,
    system=800, history=2400, retrieval=4000,
    query=200, output_reserve=1500
)
for k, v in plan.items():
    print(f"  {k}: {v}")
