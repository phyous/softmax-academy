Why does tokenization directly affect cost and latency?

Quick Take

LLM APIs bill per token. Transformer attention scales quadratically with sequence length. Two prompts that look the same length to a human can cost wildly different amounts depending on how they tokenize.

Deep Dive

Every token processed costs compute and money. Input tokens are charged at one rate, output tokens typically at 2–4x more. But cost is just the start — transformer self-attention has O(n²) complexity in sequence length, so doubling your prompt doesn't just double cost, it roughly quadruples the attention computation.

This is why token-efficient prompting isn't just a billing concern: it directly affects latency, throughput (how many requests your GPUs can serve), and whether your system stays responsive under load. Engineers who measure token counts before shipping prompts avoid surprise bills and timeout errors.

Code

import tiktoken

enc = tiktoken.encoding_for_model("gpt-4")

def estimate_cost(text, input_rate=0.03/1000, output_tokens=500, output_rate=0.06/1000):
    """Estimate API cost for a prompt + expected output."""
    input_tokens = len(enc.encode(text))
    input_cost = input_tokens * input_rate
    output_cost = output_tokens * output_rate
    total = input_cost + output_cost
    return {
        "input_tokens": input_tokens,
        "output_tokens": output_tokens,
        "input_cost": f"${input_cost:.4f}",
        "output_cost": f"${output_cost:.4f}",
        "total_cost": f"${total:.4f}"
    }

# Natural language vs JSON encoding of the same info
natural = "Alice is 30 years old and lives in New York."
json_fmt = '{"name": "Alice", "age": 30, "city": "New York"}'

for label, text in [("Natural", natural), ("JSON", json_fmt)]:
    result = estimate_cost(text)
    print(f"{label}: {result}")
